## 5. Source and scope reconciliation

**Verified from current project documents:**
- Scout supplies trusted employer-sourced vacancies to Thungatha; it is not a public job-search frontend.
- Employer official careers publication is the source authority; an ATS is an access mechanism, not proof of employer identity.
- Initial discovery scope is Cape Town; discovery must not be narrowed by industry or job title.
- Unresolved identity, source permission and location must remain unresolved rather than guessed.
- Temporary source failures must not be interpreted as zero jobs or expired vacancies.
- Human approval is required before publishing; AI cannot approve or publish autonomously.
- The proposed stack is one Azure Functions Python v2 Function App, a separate React/TypeScript/Vite admin frontend, Azure Table Storage for Scout state, Supabase for approved Thungatha-facing records, and Google Gen AI/Groq behind a small interface. These remain proposed choices where the architecture document says they need verification/review.

**Unresolved authority conflict:**
- `AGENTS.md`, `IMPLEMENTATION-PLAN.md`, and `AI-WORKING-GUIDE.md` require reading `THUNGATHA-SCOUT-SOURCE-OF-TRUTH.md`, but that file is missing from all five inspected branch trees.
- The user-provided `main-aim.txt` and `ARCHITECTURE-AND-TECHNOLOGY.md` provide current context, but do not establish whether they supersede or fully reproduce the missing historical decision record.
- The older feature branch's API and geography filtering behavior must not override the current Cape Town scope and the separation between source verification, location eligibility and role relevance.

**Decision needed:** locate/restore the missing source-of-truth document or explicitly approve a dated change to the repository instructions identifying which existing documents are authoritative. Do not create a competing source-of-truth file by assumption.
